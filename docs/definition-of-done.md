# 完了の定義（Definition of Done）

開発者（Issue を実装する Claude Code・Codex）が「この Issue の作業は終わった」と判断するための、すべての Issue に共通の基準。
Issue ごとの条件（受け入れ条件）を満たすことに加えて、毎回この表を満たす。

- **使う場面**: 開発者が PR を作るとき（implement-issue 手順5）に1項目ずつ確かめ、結果を PR 本文に表で書く（開発者の自己チェック）。相互レビューでは、表に書いたことが本当かを確かめる。開発チームは一次判断（どちらの PR を推すかを決める手順）の中で、両方の PR の表がそろっているかを見る。直す担当（修正ワーカー）が直したときは、その担当が確かめ直し、表を新しい SHA で書き直す
- **含めないもの**: 人間の実機確認、PO の受け入れ確認、マージ。それぞれの場面で判断する
- **直し方**: プロジェクトに合わせて足しても消してもよい。準備（setup-project）で作るものに合わせて直し、その後はふりかえりで人間が採用したときに直す
- **プロジェクトの決まりとの関係**: この表は CLAUDE.md の「守ること」や `docs/testing.md` を指している。細かいことはそちらに従う

## 基準

| 項目 | 満たしている状態 |
|---|---|
| 受け入れ条件 | Issue の受け入れ条件を1つずつ満たし、どう確かめたか（テスト・画面確認など）を PR に書いた |
| 確認コマンド | CLAUDE.md の「開発設定」の確認コマンドが、push した SHA ですべて通った。E2E・ミューテーションは、導入済みで対象となる場合に通した（対象と未導入時の扱いは `docs/testing.md`） |
| テスト | `docs/testing.md` に従った（機能追加・振る舞いの変更では、テストを先に書き、対象の振る舞いで失敗することを確かめてから作った） |
| 画面 | 画面を含むなら、「開発設定」の画面確認の幅で表示と操作を確かめ、環境・幅・操作・結果を PR に書いた |
| 追随 | 変えた名前・用語・数値・手順を `git grep` で探し、ほかの文書・ガイド・コメントに古い記述が残っていない。CLAUDE.md を直したら AGENTS.md もそろえた |
| 計画 | 承認された計画で約束したことを省いていない |
| 決まり | CLAUDE.md の「守ること」に沿っている（スコープ外のことをしない、1つの PR で1つの Issue だけを扱う、公開してはいけない情報を書かない、文章の決まり、など） |
| PR 本文 | 「何をしたか」「どう確認したか」「確認したいこと」と、この表の結果を書いた。確認の結果は push した SHA のもので、CI を待たずに出すときは「CI は実行中」と SHA を書いた |

## PR 本文に書く表

```markdown
| 項目 | 結果 | 根拠 |
|---|---|---|
| 受け入れ条件 | ○ | 条件ごとのテスト名・画面確認の記録 |
| 画面 | 対象外 | 画面を変えていない |
```

- 結果は「○」か「対象外」にする。対象外には理由を書く
- 満たせない項目が残るあいだは、終わっていない。環境の都合で確かめられないものだけは、理由と確かめられなかった範囲を書き、「確認したいこと」にも載せる
