## 2. 目的と範囲

通常状態の他の駒を避ける通り道に基づいて移動範囲の目安を出す。倒れた駒は通過だけでき、停止はできない。斜めの一歩は、脇の2マスが両方とも通常の駒なら通れない。実際の移動は制限しない（範囲外の空きマスへも動かせる）。前提の #7・#9・#33・#34・#46・#50 はすべて CLOSED を確認した。スコープ外は Issue のとおり（移動の制限、足止め、経路の線、盤面サイズ、CI 短縮策など）。

## 3. 計画と承認

- 品質レビュー: 適用しない（#8・#9 以外で、人間の指定なし）。E2E は導入済みで、画面を含むため対象
- 計画は両ワーカーから Orca の ask で届いた（Codex `msg_9fab53196fc4`、Claude Code `msg_99203ed063fb`）。人間は2つを並べて見て、**両方とも修正なしで承認**した
- 共通: `getMovementRange` を「マス × 斜めの回数の偶奇」を状態にした最短経路探索に置き換える。`canMoveTo`・`tapPosition`・UI は変えない。テスト先行、E2E は重要な流れ1本
- 違い: 他の駒の渡し方（Claude Code は `{ normal: Position[]; downed: Position[] }`、Codex は `{ position, downed }[]`）、結合テストの範囲（Codex は段階をすべて通す一連の操作）
- 確認したいこと: 両者ともなし

- ADR の候補: 「目安の計算に、他の駒の状態をどの形で渡すか」。両計画で形が違う。Issue を越えて効くかは finish-issue で判断する
