## 2. 目的と範囲

駒を選びやすい大きさまで拡大して操作し、戦場全体の確認へ戻れるようにする。まず現在の10×10で、1〜4倍の拡大・縮小、スマホのピンチ・1本指ドラッグ、PC のホイール・左右ドラッグ、「全体を見る」を加える。表示操作で駒の位置・状態・選択を変えない。長押し・右クリック・「設定」は表示操作と区別する。前提の #45・#46・#60 は CLOSED を確認した。スコープ外は Issue のとおり（盤面サイズの入力 UI＝#64、駒のドラッグ移動、ルール変更、保存・共有、設定ポップアップの作り直し）。

## 3. 計画と承認

- 品質レビュー: 適用しない（#8・#9 以外で、人間の指定なし）。E2E は導入済みで、画面を含むため対象
- 計画は両ワーカーから Orca の ask で届いた（Codex `msg_340f29599895`、Claude Code `msg_9a0b5494b94b`）
- 共通: 座標ラベルを含む盤面を表示枠の中で `translate + scale` し、本物のボタンの当たり判定を使う。表示の状態 `{scale, x, y}` は App の一時的な状態（BattleState に入れない、ADR 0001 の延長）。拡大の中心・端の収まりは純粋関数。10px 超でドラッグとし長押しを取り消す。ドラッグ・ピンチ後の click を捨てる。**ADR 0007 から変える点**: マウスの右ボタンは `contextmenu` ではなく「ドラッグせず離した pointerup」で開く（macOS の Chromium は押した時点で contextmenu を出し、右ドラッグの前に開いてしまうため）。テスト先行、E2E は CDP の2点タッチとマウスの左右ボタン・ホイール
- 違い: ページの縦スクロールとの区別（Claude Code は 1倍 `pan-y`・拡大中 `none`、Codex は常に `none`）、やり直し時に表示を戻すか（Claude Code は戻さない・質問、Codex は戻す）、隠れた駒の「設定」の出し方（Claude Code のみ記載）、「全体を見る」の置き場所（Claude Code のみ記載）。Codex は画面幅の変化での収め直しと、低い画面の長押しの E2E も計画した
- コーディネーターの所見（計画時）: スコープ外・受け入れ条件の抜けなし。Codex の計画に、キーボード（Shift+F10）での設定の維持、pointer capture の開始時点、「全体を見る」の置き場所・位置ずれ・フォーカス、隠れた駒の設定の扱いの記載がなく、補足として返した
- **人間の決定（2026-11-11、「推薦どおりで承認」）**
  1. ページの縦スクロールとの区別は案A（1倍は `touch-action: pan-y`、1倍超は `none`）
  2. 「準備をやり直す」「新しい戦闘を始める」で表示も全体表示へ戻す（選択・配置・確定・状態変更では戻さない）
  3. 座標ラベルはマスと一緒に拡大・移動する
  4. 「倍率 n.n倍」を「全体を見る」と並べて表示する
  5. 盤面の上のホイールは、1倍・4倍の端でもページをスクロールさせない
  6. CI のミューテーション上限は実測の条件（手元か直近 main の CI が上限の70%超）だけで判断する
- 返信: Claude Code `msg_010530727ea1`、Codex `msg_71dffc884a36`（Codex には上の補足 A〜E を付けた）
- ADR の候補（finish-issue で判断）: 盤面の表示の状態を App に持ち計算を純粋関数にすること／マウスの右クリックは離したときに開くこと（ADR 0007 の更新）／長押しと表示操作の判定を1か所でまとめること
