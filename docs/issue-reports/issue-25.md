### 後続 Issue の案: 同じ行の別マスへの選択切り替えを回帰テストで守る

- **目的**: キャラを選んでいないときに、空きマスから同じ行の別の空きマスへ選択を切り替える操作を、画面の入口から確かめる回帰テストで守る。アプリの振る舞いは変えない
- **根拠**: spec.md 2.1「別の空きマスをタップすると選択を切り替える」。`Board.tsx:32` の判定から列（x）の比較を落とすと、同じ行の別のマスを押したときに切り替わらず解除される。この誤りを入れても、#25 の後の Vitest 67件はすべて通る（相互レビュー担当とコーディネーターが、Git 管理外のコピーで確かめた）。Stryker では対応する変異（ID 27〜29）が CompileError になり、計測されない
- **受け入れ条件の案**
  - キャラを選んでいない状態で、空きマス `(3, 4)` を選び、同じ行の空きマス `(4, 4)` を押すと、元のマスが未選択になり、押したマスだけが選択されることを確かめるテストがある（表示座標は1始まり）
  - テストは画面の入口から、実物の部品・状態管理・domain を通して操作する。モックや内部関数の公開はしない
  - 「同じ行なら、別の列でも同一マスとして解除する」という誤りを、追加したテストが検出できる。Stryker では計測できないので、Git 管理外のコピーに手で誤りを入れ、追加前は通り、追加後は対象の assertion で失敗することを記録する。追跡中のソースに誤りを残さない
  - 追加前後で通常テストが成功する。test / typecheck / lint / build・既存 E2E・全対象のミューテーション・CI が成功し、ミューテーションの結果が #25 の後から悪くなっていないことを PR に記録する
- **スコープ外**: 操作仕様・見た目の変更、#9 のキャラ操作、ミューテーション基盤や Stryker の設定の変更、依存の追加、E2E への重複追加
- **依存先**: #25（PR #28）の main 取り込み後に着手する（同じ `src/App.test.tsx` に追加するため）。#9 への依存は設けない
