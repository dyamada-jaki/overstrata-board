## 2. 目的と範囲

拡大・移動しても、見えているマスの列・行の番号を読めるようにする。番号は表示枠の上端（列）と左端（行）に残す。現在の 10×10 で操作を整えてから #64（30×30 までの盤面サイズ）へ進む。

スコープ外は Issue のとおり。盤面サイズの入力 UI と 30×30 での確認（#64）、倍率上限の変更、座標の入力・選択による移動、ゲームルールの変更、保存・共有、設定ポップアップの作り直し。

## 3. 計画と承認

### 両者の計画（2026-11-12 16:0x JST に受信）

**共通**
- 盤面を「左上の空き角＋上の列番号の帯＋左の行番号の帯＋マスの表示枠」の 2×2 にする。transform で拡大・移動するのはマスだけ
- 帯は 24px（1.5rem）、数字は 0.8rem で、倍率によらず一定。1倍の見た目と 375px での幅の使い方は今と同じ
- 番号の位置は、App が持つ `View` と表示枠の実測の大きさから純粋関数で計算する。列は横、行は縦の動きにだけ追従する
- テストを先に書く（RTL・純粋関数・E2E）。E2E では指を複数回動かす
- 帯はフォーカスを受けない。帯は固定の大きさなので、盤面の下の部品の位置はずれない

**Claude Code（[#69](https://github.com/dyamada-jaki/overstrata-board/pull/69)）**
- 計算は `boardView.ts` に `axisLabels` を追加（ミューテーションの対象のまま。設定は変えない）
- 端で切れた番号は、見えている部分の中央に寄せる。見えている部分が 16px 未満なら出さない
- 帯・角も表示操作の範囲に含める。ADR 0008 の「イベントを受ける要素」と「基準の表示枠」を分ける

**Codex（[#68](https://github.com/dyamada-jaki/overstrata-board/pull/68)）**
- 計算は新しい `boardLabels.ts`（`stryker.config.mjs` に追加）
- 端で切れた番号も常に出す。20px の箱、隣の番号を寄せる、細い断片には引出線、境界に目盛
- 帯は操作の対象にしない（帯の上から始めた操作の扱いは計画に無かった）
