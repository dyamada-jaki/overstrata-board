## 1. このアプリは何か

TRPG「Overstrata」の**プレイ中に使う戦闘ボード**。戦場のマス目・キャラの位置・移動できる範囲を画面に出し、選択したキャラを動かせる。

- **使う場面**: 音声でプレイしている卓で、戦闘中の位置関係をみんなで確認する
- **今回目指す完成形**: GM とプレイヤーがそれぞれの端末で同じ盤面を見て、GM は敵、プレイヤーは自分のキャラを配置・移動できること。移動範囲を確認し、操作するキャラを自分で選んで動かせること。行動順・手番管理は保留とする
- **部屋の継続利用**: 同じ部屋の URL を複数の戦闘で使い回す。味方キャラの登録情報と担当を引き継ぎ、戦闘ごとに盤面・敵・配置を準備し直す
- **Sprint 1 の形**: 1台の端末でサンプルキャラの表示・移動を試せる状態を作る。完成形へ進む途中の動作確認であり、この段階で実際の卓に投入することを必須にはしない（→ 4章）
- **入力**: キャラや位置はアプリ上で手入力する（AI-GM の出力を読み込むのは将来）
- **完成形に含めないもの**: 行動順・手番管理は保留。HP 管理と行動履歴の記録も後の候補。今回の完成条件には含めない

### 原則: ルールは補助のみ（自由優先）

アプリはルールを**強制しない**。移動範囲などを「見せる」だけで、最終判断は GM とプレイヤーがする。
例: 移動範囲の外にもキャラを動かせる。

行動順は卓で扱い、アプリは手番によるキャラの自動選択や操作の制限を行わない。利用する場面を狭めないよう、行動順・手番管理の機能追加はいったん保留とする（2026-10-18）。

### 実行環境: 開発も本番もコンテナで動かす

- Docker で動く前提にする（OrbStack など Docker 互換のランタイムでもよい）。ホストに Node を入れなくても開発できるようにする
- **開発**: `docker compose up` で開発サーバーが起動し、ホストのブラウザで開ける。テスト・型チェック・Lint・ビルドもコンテナの中で実行できる
- **本番**: ビルドしたファイルを Web サーバーで配信するイメージを作る。共有を入れるまでは、アプリ自体はサーバー処理を持たない（ブラウザだけで完結する）
- 共有・保存の方式と、それに必要なサーバー処理や外部サービスは未決定。部屋を継続利用する要件を踏まえ、区切り2の実装前に設計する
- どこにデプロイするかは決めていない。区切り2で扱う（→ 4章）。本番もコンテナで動かす方針を変更する場合は、先にこの仕様を更新する

## 2. 画面と操作

### 2.1 盤面

- 各マスは正方形。盤面全体は正方形または長方形
- 初期値は **10×10**。Sprint 1 ではサイズ変更の操作を作らない
- 盤面の縦・横のマス数は1か所で変更できるようにし、表示と盤面を使う計算で同じ設定を参照する
- 区切り3では、戦闘ごとに GM が縦・横のマス数を指定する。**縦・横それぞれ最大30マス**を当面の上限とする。L字形や欠けた盤面、上限の拡張は今回扱わない
- 座標ラベル: 列・行とも **1から始まる数字**。列は左から右へ、行は上から下へ増える。初期の10×10では両方とも1〜10を表示する
- 座標は **`(横, 縦)`**、つまり列→行の順で書く。括弧・カンマは半角で、カンマの後に半角スペースを1つ置く。左上は **`(1, 1)`**、10×10の右下は `(10, 10)`、30×30の右下は `(30, 30)`。音声では「横3、縦4」のように伝えられる
- 内部座標は `Position { x, y }`（0始まり。左上は `{ x: 0, y: 0 }`）。表示では `x + 1`・`y + 1` に対応する数字を使う。内部座標と表示文字列の双方向の変換は `src/domain/` の純粋関数にし、次の例を含むテストを付ける。Sprint 1 では正規の座標表記を扱い、座標の自由入力画面は作らない

| 内部座標（0始まり） | 表示文字列（1始まり） |
|---|---|
| `{ x: 0, y: 0 }` | `"(1, 1)"` |
| `{ x: 9, y: 9 }` | `"(10, 10)"` |
| `{ x: 2, y: 3 }` | `"(3, 4)"` |
| `{ x: 29, y: 29 }` | `"(30, 30)"` |

- 選択状態は「未選択」「空きマス1つを選択」「キャラ1体を選択」のいずれか。複数の対象を同時に選択しない
- キャラを選択していないとき、空きマスをタップするとそのマスを選択する。同じマスを再タップすると解除し、別の空きマスをタップすると選択を切り替える
- マス選択中にキャラをタップすると、マスの選択を解除してキャラを選択する。キャラの選択・移動は2.3に従う
- 選択したマス・キャラは枠で強調する。キャラの移動範囲は薄い色で塗り、選択対象と区別する
- 盤面外の余白をタップしても選択は変えない。キャラの位置や移動範囲の表示も変えない

### 2.2 キャラ

- 盤面にはキャラがコマ（トークン）として置かれる。1マスに1体まで
- サンプルが持つ情報（Sprint 1 / #9。#32より前の仕様）
  - 名前
  - 味方か敵か（色で見分けられるようにする）
  - 装備の重さ: 軽装 / 中装 / 重装（移動力が決まる → 3.2）
- Sprint 1 ではサンプルのキャラ4体（味方2・敵2）が置かれた状態で始まる。#32では、下記の数指定から始まる準備画面へ置き換える。配置を保ったままの追加・削除は#33で扱う
- 完成形では **GM が味方・敵の全キャラを登録する**。登録と盤面への配置は別の操作とする（→ 2.5・2.6）
- 敏捷の登録は、保留中の手番管理を再検討する場合の候補。現時点では追加を要求しない

Sprint 1 のサンプルは次の4体とする。汎用の名前を使い、vault の設定は使わない。移動力は3.2から計算する（表の値は確認用）。

| 名前 | 陣営 | 装備 | 移動力 | 初期位置（表示座標） |
|---|---|---|---|---|
| 味方1 | 味方 | 軽装 | 5 | (3, 8) |
| 味方2 | 味方 | 重装 | 3 | (6, 9) |
| 敵1 | 敵 | 中装 | 4 | (4, 3) |
| 敵2 | 敵 | 軽装 | 5 | (7, 2) |

3種類の装備をすべて含む。味方1の `(3, 8)` から敵1の `(4, 3)` までの距離は5であり、距離は移動力以内でも他キャラのいるマスは移動範囲から除かれることを確認できる。

上の装備とサンプル表は#9時点の仕様として残す。#32で用意する駒は、陣営・番号とそれに基づく名前（味方1、敵1など）、移動力、未配置か配置済みかと盤面上の位置を扱う。装備の指定は行わず、移動力は全駒5マスとする。名前の編集は後の拡張候補とする。

#### 駒の準備の最初の段階（#9以降）

2026-10-18、戦闘に合わせた駒の準備は、次の小さな形から始めることで合意した。

- 敵・味方それぞれの数を指定して、その数の駒を用意できる
- 陣営は色、同じ陣営の駒は番号で見分けられる（例: 味方1・味方2、敵1・敵2）
- 用意した駒を盤面の空きマスへ自由に配置し、配置後は選択して動かせる。1マス1体と移動操作は2.2・2.3に従う
- 準備後も、戦闘の途中で必要に応じて駒を追加・削除できる
- 倒れた駒はそのまま盤面に残せる。倒れたことを理由に自動で削除しない
- 自分の画像のアップロードと名前の編集は、後の拡張候補とする。最初の駒の準備には含めない

#32は、複数端末共有を待たず、準備から駒の選択・移動までを1台で使える形で先に作る。起動時に空の10×10盤面と「味方の数」「敵の数」の入力欄、「駒を用意する」ボタンを表示する。数を指定してボタンを押すと、指定した数の駒が未配置一覧に並ぶ。#9のサンプル4体を置いた開始画面は、この準備画面へ置き換える。

最初に指定できる数は味方・敵それぞれ0〜10体の整数（合計最大20体）とし、入力欄の初期値は双方0体とする。片側を0体にして、もう片側だけの駒を用意することもできる。#32では、駒を用意した後に数を変えたい場合は「準備をやり直す」で全駒と設定を消し、数の指定からやり直す。配置を残したままの追加・削除は、準備中も含めて後続の#33で扱う。

#32では、双方0体の間は空の盤面を表示したまま、「駒を用意する」を押せない状態にする。両方の数が許容範囲内で、どちらかが1体以上になると押せる。双方0体のままでは駒を用意せず、準備も確定しない。

数の入力操作は、#32の計画承認で次のとおり確定した。

- 「味方の数」「敵の数」は、数字用キーボードを使う直接入力（`type="text" inputmode="numeric"`）と、その左右の「−」「＋」で指定する
- 「−」「＋」は1ずつ増減し、0の「−」と10の「＋」は押せない
- 前後の空白を除いた半角数字だけで値が0〜10なら有効とする（`05`は5、` 3 `は3）
- 空欄、半角数字以外（全角を含む）、小数、負数、11以上は不正。その欄の直下に「0〜10の整数で入力してください」と表示し、`aria-invalid`と説明を入力欄に結び付ける
- 不正な欄の「−」「＋」は押せず、一方でも不正な場合は「駒を用意する」も押せない
- 双方0体の場合は入力エラーにせず、通常の案内として「味方か敵を1体以上にしてください」と表示する

#32では、用意する駒の移動力を全駒5マス固定とし、移動力や装備の重さを選ぶ操作は設けない。移動範囲は目安として表示し、範囲外への移動も可能とする（2.3・3.2）。

駒ごとの移動力設定は、#32の次に作る#37で追加する。GMが準備中に0〜9マスの整数で設定し、初期値は全駒5マスとする。装備による自動補正は行わない。未配置・配置済みのどちらも「確定」までは変更でき、設定した値を移動範囲の目安へ反映する。負数・小数・10以上は設定できない。移動力0でも盤面内の空きマスへ自由に動かせる。戦闘途中での移動力の変更は、後の拡張候補とする。

#37の移動力は、数値を表示専用にし、「−」「＋」だけで設定する（2026-10-23）。

- 現在の値を「−」と「＋」の間に表示する。数値の直接入力や削除はできない
- 「−」「＋」は1ずつ増減し、0の「−」と9の「＋」は押せない。常に0〜9の整数を保つ
- 値を変更すると、その駒の移動力をすぐ更新する。配置済みで選択中の駒は、移動範囲の表示にもすぐ反映する

#32の数入力・未配置一覧・確定などの操作は、スマホでは盤面の下、PC幅（64rem以上）では盤面の右に置く。未配置一覧は盤面と同じ陣営色の丸に番号を表示し、その下に名前を表示する。味方と敵を別の行に分け、番号順に折り返す。

#37の移動力の設定欄（数値と「−」「＋」）は、準備中に選択した駒について、操作パネルに1つ表示する。操作パネルはスマホでは盤面の下、PC幅（64rem以上）では盤面の右に置く。未配置・配置済みのどちらも同じ設定欄で扱い、駒名・陣営色の丸・番号で対象を示す。変更は選択中の駒だけに反映する。スマホでは、盤面上の駒と設定欄を行き来するための縦スクロールを許容する。

設定欄の置き場所は、2026-10-23の利用者によるスマホ実機でのPR #40・#41の比較を受け、この操作パネルに確定した。細かな見た目や操作感は、引き続き実装した画面を利用者と見ながら調整する。

最初の配置操作は、スマホで次の順にタップする形とする。

1. 盤面の外に、未配置の駒を一覧で表示する
2. 一覧から置きたい駒をタップして選ぶ
3. 盤面の空きマスをタップすると、その駒を配置する
4. 用意した駒をすべて配置し、GMが「確定」を押すと準備が完了する

準備中も選択対象は1つとする。未配置・配置済みを問わず、選択中の駒をもう一度タップすると選択を解除する。別の駒をタップすると、どの駒も移動・配置せず、タップした駒へ選択だけを切り替える。未配置の駒を選択中に、既に駒がいるマスを押した場合も、その駒への選択切り替えとなる。未配置の駒を空きマスへ置いた後は、駒・マスの選択と移動範囲の表示を解除する。

「確定」を押すまでは、配置済みの駒の位置を修正できる。全駒を配置しても自動では確定せず、未配置の駒が残っている間は確定できない。確定後は配置を引き継いで駒を選択・移動できる。「確定」時は、駒・マスの選択と移動範囲の表示を解除する。#32の移動力は準備中・確定後とも全駒5マス固定とする。

#37では、盤面に置いただけでは移動力を確定せず、「確定」を押すまで個別に修正できる。確定時に各駒の移動力を引き継ぎ、確定後の移動力の変更操作は提供しない。

#32では、全体をクリアして最初の準備画面へ戻る操作を、段階に合わせて提供する。

- 駒を用意した後の準備中は「準備をやり直す」。今の戦闘の準備を最初からやり直す。数を指定する段階では表示しない
- 確定後は「新しい戦闘を始める」。次の戦闘の準備をゼロから始める

消す前の確認はアプリ内の確認画面で行う。見出しは「準備をやり直す」または「新しい戦闘を始める」とし、本文で目的と全駒・数の設定が消えることを案内する。実行ボタンはそれぞれ「やり直す」「始める」、取り消しは「キャンセル」とする。

確認中は背後の盤面やボタンを操作できない。開いたときは「キャンセル」にフォーカスを置き、ボタン間のTab・Shift+Tabは確認画面内を循環する。Escも取り消しとして扱う。取り消した後は開いたボタンへ、実行した後は最初の「味方の数」の入力欄へフォーカスを戻す。

どちらも押すと全駒と設定を消すことを確認し、実行すると未配置・配置済みの全駒と設定を消して、最初の準備画面へ戻る。盤面は空の10×10、敵・味方の数は双方0体、マス・駒は未選択となり、移動範囲の表示も消える。新たに用意する駒の移動力は5マスとする（#37で設定機能を加えた後も初期値は5マス）。「新しい戦闘を始める」でも準備から始まり、駒を用意・配置して改めて「確定」する。確認を取り消した場合は、その時点の内容・選択状態・準備中または確定後の状態を保つ。1手順ずつ戻す機能は後の拡張候補とし、今回には含めない。

#9は従来どおり固定サンプル4体の表示・移動を扱う。その後の要件整理として、駒の準備・配置を[#32](https://github.com/dyamada-jaki/overstrata-board/issues/32)、移動力設定を[#37](https://github.com/dyamada-jaki/overstrata-board/issues/37)、途中の増減を[#33](https://github.com/dyamada-jaki/overstrata-board/issues/33)、倒れた駒の表示を[#34](https://github.com/dyamada-jaki/overstrata-board/issues/34)へ先行登録した。この順に進め、追加・削除の操作と番号の扱いは#33への着手前に相談して決める。

倒れた駒の表示は、陣営色を残して暗めにし、番号と選択枠を読み取れるようにする案を検討中。「倒れた／通常」を手動で切り替え、倒れた状態でも移動できる案を#34にまとめた。表示と切り替え操作は、着手前に確定する。

### 2.3 移動

| 状態 | タップする対象 | 結果 |
|---|---|---|
| 未選択、または空きマスを選択中 | キャラ | マスの選択を解除してそのキャラだけを選択し、枠で強調する。**移動できる範囲**を薄い色で表示する |
| キャラを選択中 | 選択中のキャラ | 位置を変えず、選択と移動範囲の表示を解除する。マスも未選択になる |
| キャラを選択中 | 別のキャラ | どのキャラも移動せず、タップしたキャラへ選択を切り替える。枠と移動範囲の表示も切り替える |
| キャラを選択中 | 空きマス | 選択中のキャラがそのマスへ移動する。移動後は選択と移動範囲の表示を解除し、移動先のマスも未選択になる |

範囲の外の空きマスにも移動できる（1章の原則）。他のキャラがいるマスには移動できず、そのキャラをタップした場合は上表のとおり選択だけを切り替える。

キャラ未選択時の空きマスの選択・再タップでの解除・切り替えと、盤面外の余白タップは2.1に従う。

移動できる範囲 = 移動力（3.2）以内の距離（3.1）にあり、盤面の中で、他のキャラがいないマス。
他のキャラを「通り抜けられるか」はまだ考えない（→ 5章の未決事項）。

実際に移動できるかの判定も `src/domain/` の純粋関数にし、テストを付ける。盤面内の空きマスなら移動範囲外でも移動でき、他キャラのいるマスや盤面外には移動できない。移動範囲の表示と移動先の可否を区別し、移動力によって移動操作を禁止しない。

### 2.4 画面の前提

- スマホの縦画面（幅 375px）を基準に作る。PC でも崩れなければよい
- 10×10 の盤面は、幅 375px で横スクロールなしに全体が見え、マスを指でタップできる
- 開発中の画面は、同じ LAN のスマホから開けるようにする（実機で確かめるため。開発サーバーを LAN に公開する）
- 画面の文言は日本語

画面の確認は次のように分担する（→ workflow.md ステップ5・6）。

- **エージェント**: 操作できるブラウザまたは iOS シミュレーターを使い、幅375pxの画面で表示・操作を確認する。利用した環境・画面幅・確認した操作と結果を PR に書く。DOM のテストだけで画面確認済みとはせず、確認できなかった場合は理由と未確認項目を残す
- **人間**: レビュー時にスマホ実機で、同じ LAN から開けること、全体の見え方、指での選択・移動・解除のしやすさを確認する。エージェントの PR 作成に実機確認は要求せず、人間の確認結果をレビューに残す

### 3.0 ルールの正本はどこにあるか

- vault は**読むだけ**。アプリ側の都合で vault を書き換えない（ルールを直す判断はPO の席で人間がする）

### 3.1 距離の数え方（移動）

**縦・横は1マス=1。斜めは1マス目=1、2マス目=2、3マス目=1…と交互に数える。**

横の差を dx、縦の差を dy とすると: 距離 = `max(dx, dy) + floor(min(dx, dy) / 2)`

| 動き | 距離 |
|---|---|
| 右へ3 | 3 |
| 斜めに1 | 1 |
| 斜めに2 | 3 |
| 斜めに3 | 4 |
| 斜めに4 | 6 |
| 右へ4・下へ2 | 5 |

向きが逆でも距離は同じ。

### 3.2 移動力

Sprint 1（#9）のサンプルには、次のOverstrataの移動力を使う。

- 基本 **5マス**
- 装備の重さで補正: 軽装 ±0 / 中装 −1 / 重装 −2（つまり 5 / 4 / 3）
- この数値はゲーム側で仮の値。後で変わる前提で扱う

#32で用意する駒の移動力は全駒5マス固定とする。後続の#37で、GMが準備中に駒ごとに「−」「＋」で設定できるようにする（0〜9マスの整数、初期値5マス）。どちらもアプリで装備の重さによる補正は行わない。移動範囲は、その値と3.1の距離の数え方で求める。戦闘途中での値の変更、10以上の移動力への拡張、瞬間移動のような特殊な移動の専用機能は後の拡張候補とし、#32・#37には含めない。移動範囲の外へ自由に動かせる原則は維持する。

### 3.3 手番と行動のルール（参考・アプリへの導入は保留）

以下は Overstrata のルールの参照情報。アプリでの行動順・手番管理は保留であり、選択・移動をこれらのルールで制限しない。

- 1手番の行動は次の5つのどれか1つ（移動を攻撃の前後に分けない）: ただ近づく / 近づいて攻撃 / その場で攻撃 / 攻撃して離れる / ただ離れる
- すれ違いざまの攻撃（機会攻撃）という概念はない
- 手番の順は敏捷の高い順で固定。自分の手番に「そのラウンドの最後まで遅らせる」を選べる。遅らせた者同士は元の敏捷順に並ぶ
- 敏捷が同じキャラ同士の順番は、卓で会話して決め、GM が並べる

手番管理は今回の完成形に含めない。再検討する場合は、必要な補助と操作の自由を改めて相談する。行動5パターンの記録は将来の候補とし、記録内容や用途はまだ決めない。

### ゲーム設計（vault）との関係

このアプリの仕様を決める過程で、vault の記述と食い違った点と、その決着。

| 論点 | 決着 |
|---|---|
| 移動の数え方 | vault の `コア設計.md` §6.8 は当初「移動＝縦横のみ（斜め移動なし）」だった。**斜め交互 1→2 を採用**し、vault 側にも記録済み（2026-09-28） |
| 端末の数 | vault の §6.6 は「1台を全員で囲む」。このアプリは**複数端末での共有を目標にする**（相棒の決定）。vault 側をどう直すかはPO の席の判断に委ねる |
| 盤面サイズ | vault の §6.8 は通常戦闘 20×20 前後が目安。このアプリは**初期値 10×10、可変で上限30×30**。大きな盤面は全体表示と拡大・縮小・表示位置の移動で扱う（2026-10-14決定、詳細は2.1・2.4） |
| 座標の表記 | 当初は vault の「B4」「C7」に合わせていた。2026-10-15に、アプリの表示を1始まりの `(横, 縦)` に変更することを決定。位置や距離のルールは変えず、アプリ側の表示方法として扱う |
