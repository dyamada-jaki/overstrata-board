# 0002. 駒は番号・移動力・未配置を自分のデータとして持つ

- 状態: 採用
- 日時: 2026-10-23 17:00 JST（人間が採用した日時）
- 関連: Issue #32 / 採用 PR #38 / [Issue レポート](../issue-reports/issue-32.md)

## 背景
#9 の `Character` は装備の重さ（`armor`）を持ち、移動力は装備から計算していた。表示する番号を持たず、全駒が盤面に置かれている前提だった。#32 で、数を指定して用意した駒を未配置一覧から置く流れと、全駒5マス固定の移動力が加わり、その後の #37 では駒ごとに移動力を指定する（[spec.md 2.2・3.2](../spec.md#32-移動力)）。

## 決定
駒（`Character`）のデータは `{ id, name, side, number, movement, position: Position | null }` とする。
- 未配置は `position: null` で表す。配置済みかどうかを別の一覧やフラグで持たない
- 盤面や一覧に出す番号は `number` から表示する。名前の文字列から番号を取り出さない
- 移動力は `movement` に駒ごとの値として持つ。装備から計算しない

## 理由
- 名前の末尾の文字から番号を取ると「味方10」が「0」になる（#9 の不採用 PR #36 の `name.slice(-1)`）。陣営の色と番号で最大10体ずつを見分ける要件を満たせない
- 未配置と配置済みを同じ一覧で扱えるので、選択の切り替えや全体のクリアが単純になる
- #37 の「駒ごとに 0〜9 マスを直接指定する」に、そのまま値を差し替えるだけで対応できる
- 二重実装の両 PR（#38・#39）が同じ形を選んだ

## 選ばなかった案
- `armor` から移動力を計算する（#9 の作り）：#32 以降は装備による補正を行わない（spec.md 3.2）
- 未配置の駒を別の一覧で持つ：配置のたびに2つの一覧を同期する必要がある

## 影響
- 移動範囲の計算は `movement` と `position` を使う。`position` が `null` の駒は範囲を持たず、他の駒の占有にも数えない
- #33 で途中の増減を入れるときは、`number` の付け方（欠番・再利用）を着手前に決める
- 装備の重さの計算（`src/domain/movement.ts`）と `Armor` 型は、#9 のサンプルの仕様として残っている。使わなくなった時点で整理を検討する
