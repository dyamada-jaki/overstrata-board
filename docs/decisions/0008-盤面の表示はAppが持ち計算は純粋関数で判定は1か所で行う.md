# 0008. 盤面の表示（倍率・位置）は `App` が一時的な表示の状態として持ち、計算は純粋関数、操作の判定は1か所で行う

- 状態: 採用
- 日時: 2026-11-12 14:05 JST
- 関連: Issue #63 / 採用 PR #65 / [Issue レポート](../issue-reports/issue-63.md)

## 背景
#63 で盤面を1〜4倍に拡大・縮小し、表示位置を動かせるようにした（[spec.md 2.4](../spec.md#24-画面の前提)）。スマホのピンチ・1本指のドラッグ、PC のホイール・左右のドラッグを、既存のタップ（選択・配置・移動）、長押し、右クリック（[ADR 0007](0007-駒への補助操作は長押しと右クリックで受け設定はモーダルのdialogで出す.md)、0009 で置き換え）と区別する必要があった。後続の #64（30×30 までの盤面）と、拡大時の座標ラベルの見せ方も、この表示の上に作る。

## 決定
- **状態の持ち方**: 表示 `View { scale, x, y }` は `App` の一時的な表示の状態として持ち、ゲームの状態（`BattleState`）には入れない。`Board` は `view` を受け取って `transform` で描き、変更は `onViewChange` で通知する（[ADR 0001](0001-画面の状態は最上位の部品が持ち盤面は表示だけにする.md) の延長）。「全体を見る」「準備をやり直す」「新しい戦闘を始める」で `initialView` に戻す
- **計算**: 倍率と位置の計算は、React に依存しない純粋関数（`src/components/boardView.ts` の `clampView`・`zoomAt`・`panBy`）にする。1倍は「盤面全体が表示枠に収まる大きさ」とし、表示位置は盤面が枠からはみ出した分だけ動ける範囲に収める。ゲームのルールではないので `src/domain/` には置かない
- **操作の判定**: 盤面の表示操作は `src/components/useBoardGestures.ts` の1か所で判定する
  - ドラッグの開始は、長押しの取り消しと同じ 10px（`longPress.tolerance`）を超えたとき。開始時とピンチの開始時に長押しを取り消し、その後の click を1回だけ止める（キーボードの click は止めない）
  - 指・マウスの追跡を表示枠に移す（`setPointerCapture`）のは、ドラッグが始まってから。押した時点では移さず、タップの click の届き先を変えない
  - 表示の更新は、前の表示からの差分（`setView(view => …)`）で行う。ドラッグ中にホイールが来ても倍率を巻き戻さない
  - ホイールはネイティブの `wheel`（`passive: false`）で受け、盤面の上ではページをスクロールさせない。`deltaMode` は 1行 = 16px、1ページ = 表示枠の高さとしてピクセルに換算する
  - 表示枠の大きさが変わったら（`ResizeObserver`、無い環境は `window` の `resize`）、倍率を保ったまま `clampView` で収め直す
  - 1倍では `touch-action: pan-y`（ページの縦スクロールを残す）、1倍より大きいときは `none`

## 理由
- 二重実装の両計画（PR #65・#66）が、独立に「表示の状態は上位が持ち、計算は純粋関数」を選び、人間が計画を承認した。計算を純粋関数にしたので、境界（1〜4倍、端の収まり、基準点を動かさない拡大）を jsdom なしで確かめられた
- 不採用の PR #66 は、ピンチの開始時にも追跡を枠へ移し、子要素から伝わった `lostpointercapture` で操作全体を取り消していた。そのため、スマホで1歩目のあとにドラッグが止まった（相互レビューの必須の指摘、人間の実機確認でも再現）。ドラッグを開始時点の表示から計算していたので、ドラッグ中のホイールで倍率が戻った。採用した作りはこの2つを起こさない
- 相互レビューで、拡大した状態で画面を縮めると盤面が消える問題が見つかり、大きさの変化で収め直す処理を加えた（テストを先に書いて失敗を確かめた）

## 選ばなかった案
- 開始時の表示を起点にドラッグ量を足す作り、ピンチ開始時の追跡の付け替え、`lostpointercapture` で全体を取り消す作り（不採用の PR #66）: 上の理由のとおり
- 表示の状態を `BattleState` に入れる: 保存・共有の対象ではない一時的な見え方で、ルールの計算と混ざる

## 影響
- #64 の 30×30 や座標ラベルの見せ方は、`View` と `boardView.ts` の上に作る。座標ラベルを盤面の端に固定するなら、同じ `View` から位置を計算する
- 盤面に新しい指・マウスの操作を足すときは `useBoardGestures` と `useLongPress` の取り消しの関係を先に確かめる。10px の値を変えると、長押しとドラッグの両方が変わる
- jsdom はレイアウトと実際のタッチを持たないので、表示操作は E2E（Chromium の CDP タッチ）で、指を複数回動かして確かめる（PR #66 の E2E は1回しか動かさず、止まる問題を見逃した）
- 実際の Firefox は確かめていない。ホイールの換算を変えるときは、実際の Firefox での確認を検討する
