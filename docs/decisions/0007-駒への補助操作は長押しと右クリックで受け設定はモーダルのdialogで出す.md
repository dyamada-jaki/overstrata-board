# 0007. 駒への補助操作は長押しと右クリック（contextmenu）で受け、設定はモーダルの `<dialog>` で駒の近くに出す

- 状態: 採用
- 日時: 2026-10-31 17:37 JST（人間が採用した日時）
- 関連: Issue #45 / 採用 PR #56 / [Issue レポート](../issue-reports/issue-45.md)

## 背景
#45 で、移動力・状態の切り替え・削除を、操作パネルの常設の欄から、駒の設定ポップアップへ移した（[spec.md 2.2「駒の設定ポップアップ（#45）」](../spec.md#22-キャラ)）。通常のタップ／クリックは選択・配置・移動に残したまま、別の操作で設定を開く必要があった。外側の操作は閉じるだけに使い、背後の駒やマスに届けず、開閉で盤面や未配置一覧を押し下げないことも求められた。

## 決定
- **開く操作**: スマホは長押し、PC は右クリック（`contextmenu`）。キーボードは Shift+F10／メニューキー（`contextmenu` として届く）と、操作パネルの「設定」ボタン
  - 長押しは `pointerType` が touch か pen の `pointerdown` から計時する（`src/components/useLongPress.ts`、500ms）。10px を超える移動、`pointercancel`（ブラウザがスクロールを始めた）、`scroll`、判定時間より前の指離しで取り消す。マウスの左ボタンの長押しでは開かない
  - 長押しで開いた後に同じ操作で届く click と `contextmenu` は二重に処理しない（選択を解除しない、閉じない）
  - 駒には `-webkit-touch-callout: none` と `user-select: none` を付け、長押しでメニューや文字選択を出さない
- **開いたとき**: 対象の駒を `src/domain/` の純粋関数（`selectCharacter`。同じ駒なら選択を保つ）で選択する。既存の `tapCharacter`（同じ駒で解除）は使わない
- **出し方**: `<dialog>` を `showModal()` で開く（`src/components/PieceSettings.tsx`）。top layer に出るので文書の流れに入らず、backdrop が外側の入力を受けて背後へ届かない。外側は「backdrop で押し始めて、backdrop で click が終わった」ときだけ閉じる
- **位置**: React に依存しない純粋関数（`src/components/popupPosition.ts` の `placePopup`）で、駒の下、入らなければ上、どちらにも入らなければ画面内に収める
- **状態の持ち方**: どの駒の設定を開いているかと開いた元の要素は、`App` の一時的な表示の状態として持ち、ゲームの状態（`BattleState`）には入れない。`Board` は長押し・右クリックを `onOpenSettings` で通知するだけにする（[ADR 0001](0001-画面の状態は最上位の部品が持ち盤面は表示だけにする.md) の延長）

## 理由
- モーダルの `<dialog>` なら、外側の操作を閉じるだけにする仕様を、背後の要素ごとに防ぐ処理なしで満たせる。top layer に出るので、開閉で盤面・一覧を押し下げない
- 長押しを touch/pen の pointer で計時すると、`contextmenu` を出さない iOS Safari でも開け、スクロールの開始（`pointercancel`）で自然に取り消せる
- 二重実装の両計画（PR #56・#57）が独立に同じ作り（モーダル、500ms・10px、純粋関数の位置計算）を選び、人間が計画を承認した。人間のスマホ実機確認で、PR #56 は長押し後の文字選択と大きさ・位置が「大丈夫」だった

## 選ばなかった案
- 操作パネルに設定欄を常設する（#37〜#50 の方式）：選択のたびに欄が出入りし、選んだ未配置の駒が203px下へずれた。#45 はこの問題を直すための Issue
- モーダルでないポップオーバー（`popover` 属性や絶対配置の要素）：外側の操作が背後の駒・マスに届くため、閉じるだけにする処理を別に作る必要がある
- ポップアップを `position: fixed` で画面に固定し、駒の左端に合わせる（不採用の PR #57）：高さ309pxで、低い画面では駒に重なりやすかった。採用した PR #56 は文書座標で置き、スクロールすると駒と一緒に動く

## 影響
- 盤面のピンチ・ドラッグなどのジェスチャー（spec.md 5章）を足すときは、長押しの取り消し条件（10px 超の移動・`pointercancel`・`scroll`）と区別できるように計画する。ドラッグの開始を長押しの取り消しに使うかを、その Issue の計画で決める
- 駒への補助操作を増やすときは、同じ入口（長押し・右クリック・「設定」）とポップアップにまとめることを先に検討する
- 高さの低い画面（横向きなど）では、ポップアップが駒に重なり、長押しを離した click がポップアップ内のボタンに届く候補が残っている（後続の候補。PR #56 では未再現）。位置の計算やポップアップの大きさを変えるときは、この条件を確かめる
- jsdom はレイアウトと実際のタッチを持たないので、位置・スクロール・長押しは E2E（Chromium の CDP タッチ）で確かめる
