# 0005. 倒れた状態など駒の一時的な状態は、駒自身の真偽値（`Character.downed`）で持つ

- 状態: 採用
- 日時: 2026-10-25 JST（人間が採用した日時）
- 関連: Issue #34 / 採用 PR #48 / [Issue レポート](../issue-reports/issue-34.md)

## 背景
#34 で、倒れた駒を盤面に残し、操作パネルで「倒れた状態」と「通常」を切り替えられるようにした（[spec.md 2.2](../spec.md#22-キャラ)）。[ADR 0003](0003-確定前の追加分は戦闘の状態の一覧で持つ.md) の「影響」は、駒の状態を増やすときに「駒の性質か戦闘の段階か」を示し、[ADR 0002](0002-駒は番号と移動力と未配置を自分で持つ.md) と 0003 のどちらに沿うかを決めるよう求めていた。

## 決定
倒れた状態は、`Character` の必須の項目 `downed: boolean` で持つ。
- 切り替えは `src/domain/` の純粋関数（`toggleDowned`）で行う。移動を止める条件（配置済みで倒れている駒は空きマスへ移動しない）は `tapPosition` の中で判定する
- 表示（盤面の丸のクラス・アクセシブル名）は `src/components/piece.ts` の1か所で `downed` から決める
- ADR 0002 の駒のデータ `{ id, name, side, number, movement, position }` に `downed` が加わる。0002 の考え方（駒の性質は駒自身が持つ）に沿った追加で、0002 は置き換えない

## 理由
- 倒れているかは戦闘の段階ではなく、その駒の性質。確定・追加・削除・配置をまたいでそのまま駒に付いていき、別の一覧との同期が要らない
- 削除した駒の状態が一覧に残る、といった同期漏れが起きない
- 二重実装の両計画（PR #48・#49）が独立に同じ向きを選び、人間が計画を承認した

## 選ばなかった案
- 戦闘の状態に、倒れた駒の `id` の一覧として持つ（ADR 0003 の `pendingIds` の形）：駒を追加・削除する関数のすべてで一覧の同期が必要になる。倒れた状態は戦闘の段階ではないので、0003 の理由が当てはまらない

## 影響
- 駒の一時的な状態（今後の状態異常など）を足すときは、まずこの ADR に沿って `Character` の項目にすることを検討する。戦闘の段階に属するものは ADR 0003 に沿う
- 駒の項目が増えるので、サンプルデータや駒を作る関数では、既定値（`downed: false`）を必ず入れる
