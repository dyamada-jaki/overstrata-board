# 0010. 座標の番号は拡大・移動（transform）の外の帯に描き、表示操作は帯を含む外側で受けて、位置と大きさは表示枠で測る

- 状態: 採用
- 日時: 2026-11-12 22:45 JST
- 関連: Issue #67 / 採用 PR #69 / [Issue レポート](../issue-reports/issue-67.md) / [ADR 0008](0008-盤面の表示はAppが持ち計算は純粋関数で判定は1か所で行う.md) を補う

## 背景
#63 では座標の番号がマスと一緒に拡大・移動したので、拡大すると番号が表示枠の外へ出て読めなかった。#67 で、列の番号を表示枠の上端、行の番号を左端に残し、拡大・移動しても番号とマスの対応が合うようにした（[spec.md 2.4](../spec.md#24-画面の前提)）。後続の #64（30×30 までの盤面）も、この番号の上に作る。

## 決定
- **配置**: 盤面の外側（`.board-area`）を「左上の角・列の番号の帯・行の番号の帯・マスの表示枠（`.board-viewport`）」の 2×2 にする。`transform` で拡大・移動するのはマスだけ。番号の帯は `transform` の外に置き、`overflow: clip` で切り取る。番号は帯にだけ描く（1倍でも二重にならない）。帯は 24px、数字は 0.8rem で、倍率によらず同じ大きさにする
- **番号の位置の計算**: `View` と表示枠の実測の長さから、純粋関数 `axisLabels(count, scale, offset, length)`（`src/components/boardView.ts`）で求める。マスの並び（内側 1px の余白・間 1px）を `scale` 倍して `offset` だけずらし、見えている部分に番号を置く。全体が見えるマスは中心、切れたマスは見えている部分の中央に置く。切れたマスで見えている部分が `labelMinSize`（16px）未満なら、番号を出さない
- **操作の受け手と基準を分ける**: `useBoardGestures(area, frame, …)` は、操作を受ける要素 `area`（帯と角を含む外側）と、指・カーソルの位置と大きさの基準 `frame`（表示枠）を別々に受け取る。ホイールの listener と `setPointerCapture` は `area` に付け、`zoomAt`・`clampView` の計算は `frame` の座標と大きさで行う。ドラッグの判定・差分での更新・大きさの変化での収め直しは ADR 0008 のまま
- **補助操作**: 右ボタンの押下の記録（`notePointerDown`）と `contextmenu` の `preventDefault` も `area` で受ける（[ADR 0009](0009-駒への補助操作は長押しと右ボタンを離したときに受け設定はモーダルのdialogで出す.md)）。帯・角の上の右クリックでは、ブラウザのメニューも設定も出ない

## 理由
- 番号を `transform` の外に置くので、拡大・移動しても番号の大きさと帯の位置が変わらない。番号の位置は `View` だけから決まり、マスの transform と同じ式なので対応がずれない（E2E で ±1.5px を実測した）
- 切れた番号を出さない作りでは、出ている番号が必ず自分の列・行の上にある。人間がスマホ実機で2つの PR を見比べ、こちらを採用した
- 受け手と基準を分けたので、帯の上から始めたドラッグ・ピンチ・ホイールも盤面の表示を動かせる（計画承認で人間が決めた）。一方で、拡大の基準点と収まりの計算は #63 と同じ表示枠のまま保てた

## 選ばなかった案
- 切れた番号も常に出し、20px の箱で隣の番号を寄せ、引出線と目盛を付ける（不採用の PR #68、`boardLabels.ts` を新設）: 断片が約10px 未満だと、番号の箱が隣の列・行の上に来る。1.1倍で左上を少しずらすと「1」と「2」が列2の上に並ぶ（相互レビューで確認）
- 帯を表示操作の対象外にする（PR #68 の最初の計画）: 帯の上から始めた指の操作が何も起こさず、端を動かしにくい。人間が帯も表示操作にそろえると決めた

## 影響
- #64 の 30×30 では、1倍のマスが約10px で「10」（約15px）より狭く、全体が見えるマスの番号どうしが詰まる。間引きを入れるなら `axisLabels` に足し、この ADR を見直す
- 盤面の外側に要素を足すとき、操作を受けるのは `area`、座標の基準は `frame` であることを保つ。基準を `area` にすると、帯の幅だけ拡大の基準点がずれる
- タッチでは、マスとの境界から数 px の帯の上のタップが、ブラウザのタッチの補正でマスに届く（main・PR #68 も同じ）。spec.md で許容と決めた。帯からのタップを止める場合は、端のマスの押しやすさと合わせて仕様から決め直す
- jsdom はレイアウトを持たないので、番号とマスの対応は E2E の `getBoundingClientRect` で確かめる
