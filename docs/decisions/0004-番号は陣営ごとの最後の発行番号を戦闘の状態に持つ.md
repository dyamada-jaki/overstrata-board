# 0004. 駒の番号は、陣営ごとの最後の発行番号を戦闘の状態（`issued`）に持って発行する

- 状態: 採用
- 日時: 2026-10-25 JST（人間が採用した日時）
- 関連: Issue #33 / 採用 PR #43 / [Issue レポート](../issue-reports/issue-33.md)

## 背景
#33 で、準備中・戦闘途中に駒を追加・削除できるようになった。番号は味方・敵それぞれ1から発行順に増やして99番まで使い、削除した番号は再利用しない。全体をクリアしたときは1番に戻す（[spec.md 2.2](../spec.md#22-キャラ)）。[ADR 0002](0002-駒は番号と移動力と未配置を自分で持つ.md) の影響に「#33 で `number` の付け方を着手前に決める」と残っていた。

## 決定
`BattleState.issued`（`{ ally: number, enemy: number }`）に、陣営ごとの最後に発行した番号を持つ。
- 追加した駒の番号は `issued[side] + 1` から順に付け、`issued` を進める
- 削除しても `issued` は戻さない。「準備をやり直す」「新しい戦闘を始める」で全体をクリアしたときだけ、初期の状態（双方 0）に戻す
- 追加できる数は、同時数の上限からの残りと、99番までの残り（`pieceLimits.maxNumber - issued[side]`）の少ない方とし、判定と表示に同じ関数（`getAdditionCapacity`）を使う

## 理由
- 「最後の番号を削除しても再利用しない」（敵1・2・3から敵3を削除しても、次は敵4）を、今いる駒から数える方法では満たせない
- 発行の状況は駒が全部消えても残る必要があり、駒の一覧の外に持つ必要がある
- 二重実装の両 PR（#43・#44）が同じ形を選んだ

## 選ばなかった案
- 今いる駒の最大の番号に1を足す：最後に発行した駒を削除すると番号を再利用してしまう
- 削除した番号を記録して欠番を埋める：仕様が再利用しないと決めている

## 影響
- 駒を作る処理は、`issued` を通して番号を付ける。駒の生成を別の場所に足すときも同じ関数を使う
- 全体をクリアする処理を足すときは、`issued` も初期化する
- 保存・復帰（区切り3）を作るときは、`issued` も保存の対象に含める
