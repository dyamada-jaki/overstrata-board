# 0009. 駒への補助操作は長押しと、マウスの右ボタンを動かさずに離したとき（pointerup）に受け、設定はモーダルの `<dialog>` で駒の近くに出す

- 状態: 採用
- 日時: 2026-11-12 14:05 JST
- 関連: Issue #63 / 採用 PR #65 / [Issue レポート](../issue-reports/issue-63.md) / 置き換え元 [ADR 0007](0007-駒への補助操作は長押しと右クリックで受け設定はモーダルのdialogで出す.md)

## 背景
[ADR 0007](0007-駒への補助操作は長押しと右クリックで受け設定はモーダルのdialogで出す.md)（#45）では、PC の右クリックを `contextmenu` で受けて駒の設定を開いた。#63 で、右ボタンのドラッグでも盤面の表示位置を動かすことになった（[spec.md 2.4](../spec.md#24-画面の前提)：「駒の設定を開くのは、ドラッグせずに右ボタンを押して離した場合とする」）。macOS・Linux の Chromium は右ボタンを押した時点で `contextmenu` を出すため、0007 のままでは右ドラッグを始める前に設定が開く。変えるのは右クリックの開き方だけで、ほかは 0007 を引き継ぐ。

## 決定
- **開く操作**:
  - スマホ・ペンの長押し: 0007 と同じ（`pointerType` が touch か pen の `pointerdown` から 500ms。10px を超える移動、`pointercancel`、`scroll`、判定時間より前の指離しで取り消す）。盤面のドラッグ・ピンチの開始でも取り消す（[ADR 0008](0008-盤面の表示はAppが持ち計算は純粋関数で判定は1か所で行う.md)）
  - **マウスの右ボタン**: 駒の上で押して、10px 以内で離したとき（`pointerup`）に開く。10px を超えて動かしたら右ドラッグとして表示位置を動かし、設定は開かない
  - マウス由来の `contextmenu` は、ブラウザのメニューを止めるだけにする（盤面の上では常に `preventDefault`）。Windows のように離した後に来る `contextmenu` でも二重に開かない。空きマスから始めた右ドラッグを駒の上で離しても開かない
  - キーボード（Shift+F10・メニューキー）と Android の長押しから来る `contextmenu` は、マウスの押下を伴わないので、0007 どおり開く。操作パネルの「設定」ボタンも同じ
  - Mac の Ctrl+左クリックは、main と同じく設定が開く（Playwright の Chromium で確認）
- **開いたとき・出し方・位置・状態の持ち方**: 0007 と同じ（`selectCharacter` で選択、`showModal()` の `<dialog>`、`placePopup` で駒の下か上、どの駒を開いているかは `App` の一時的な表示の状態）。拡大で表示枠の外に隠れた駒の設定は、「設定」ボタンの近くに出す

## 理由
- 押した時点の `contextmenu` で開くと、右ドラッグと右クリックを区別できない。離したときに判定すれば、OS による `contextmenu` の時点の違いに左右されない
- 二重実装の両計画（PR #65・#66）が、独立に「`pointerup` で開く」という同じ 0007 からの変更を、理由を付けて計画に書き、人間が承認した
- 不採用の PR #66 は Mac の Ctrl+クリックで設定が開かなくなった（相互レビューの指摘）。採用した PR #65 は既存の動きを保った
- 人間の実機確認（Mac の Chrome）で、左右のドラッグと右クリックを使い分けられた

## 選ばなかった案
- 0007 のまま `contextmenu` で開く: 上の理由のとおり、macOS・Linux では右ドラッグの前に開く
- `contextmenu` を受けてから、ドラッグの有無が分かるまで開くのを遅らせる: OS ごとに `contextmenu` の来る時点が違い、遅らせる長さを決められない

## 影響
- 駒への補助操作を増やすときは、同じ入口（長押し・右ボタンを離したとき・キーボード・「設定」）とポップアップにまとめることを先に検討する（0007 から引き継ぐ）
- 右ボタンの判定は `src/components/useLongPress.ts` にあり、表示枠の `pointerdown` からも `notePointerDown` で右ボタンの押下を記録する。盤面の操作を変えるときは、この連携を崩さない
- 実際の Windows・Firefox のブラウザーでの右クリックは確かめていない。低い画面の長押し後の誤操作の候補（0007 の影響）も未解消のまま残る
